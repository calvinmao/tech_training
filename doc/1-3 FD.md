# FD

## Process in Linux Kernel

A process is a running instance of a loaded ELF executable. At the kernel level, creating a process simply means allocating a new `task_struct`. This C data structure acts as a container to hold all the various attributes required to manage the process's lifecycle.

```c
// https://elixir.bootlin.com/linux/v4.18/source/include/linux/sched.h#L593
struct task_struct {}
```

Furthermore, Linux exposes these internal details through the `/proc` virtual filesystem, allowing users to check a specific process's status via its `/proc/[pid]/` folder.

## FD

A **File Descriptor (FD)** is a fundamental attribute of a Linux process. It is a **non-negative integer** that acts as a handle, used to represent and track an opened file within that specific process.

Under the hood, this integer serves as an index into the process's file descriptor table, which is managed by the `files` pointer in the `task_struct`.

```c
struct task_struct {
	/* Open file information: */
  	struct files_struct	*files;
}

// https://elixir.bootlin.com/linux/v4.18/source/include/linux/fdtable.h#L48
struct files_struct {
	struct fdtable __rcu *fdt;
}

struct fdtable {
	struct file __rcu **fd;      /* current fd array */
};

// https://elixir.bootlin.com/linux/v4.18/source/include/linux/fs.h#L859
struct file {
	struct inode *f_inode;	/* cached value */
	unsigned int f_flags;
	fmode_t f_mode;
	loff_t f_pos;
}
```

The pointer chain to remember: `task_struct.files` -> `files_struct.fdt` -> `fdtable.fd[]` -> `struct file`.

We can also view a process's open files in the `/proc/<pid>/fd` directory. By default, the Linux kernel provides a process with the basic FDs: 0 (Standard Input), 1 (Standard Output), and 2 (Standard Error).

```c
// unistd.h
/* Standard file descriptors.  */
#define STDIN_FILENO    0       /* Standard input.  */
#define STDOUT_FILENO   1       /* Standard output.  */
#define STDERR_FILENO   2       /* Standard error output.  */
```

## System call

Linux manages all hardware and critical system resources. Because allowing user direct access to these resources is dangerous, Linux provides a secure, limited set of built-in functions (like reading a file or allocating memory), which is known as the **system call**.

To check the manual and details of any system call, you can use the `man 2` command (e.g., `man 2 open`).

### Basic system calls for file operations

- `open()`: Opens a file and returns a FD.
- `close()`: Closes the FD, releasing the resource.
- `read()`: Reads bytes from a FD into a buffer.
- `write()`: Writes bytes from a buffer to a FD.

### Write a custom `cat`

We can use these basic system calls to write a simplified version of the Linux `cat` utility. The flow is `open` -> `read` loop -> `write` to stdout (FD 1) -> `close`.

Source: [`src/mycat.c`](../src/mycat.c)

```c
#include <fcntl.h>
#include <unistd.h>

int main(int argc, char *argv[]){
  int fd = open(argv[1], O_RDONLY);
  char buffer[1024];
  ssize_t bytes_read;
  while ((bytes_read = read(fd, buffer, 1024)) > 0) {
    ssize_t bytes_written = write(STDOUT_FILENO, buffer, bytes_read);
  }
  close(fd);
  return 0;
}
```

Build and run:

```bash
gcc src/mycat.c -o mycat
./mycat /etc/hosts
ls -l /proc/$$/fd     # see your own stdin/stdout/stderr (0/1/2)
```

## Verified on machine (WSL2, Ubuntu 24.04)

`mycat` reading its own source via only the four syscalls:

```
$ gcc src/mycat.c -o build/mycat
$ ./build/mycat src/mycat.c | head -4
/*
 * 1-3 FD : a simplified `cat` built only on the four basic syscalls.
 *
 *   open()   -> get an FD for the file
```

The FD table — the most important observation. A sleep process with stdin /
stdout / stderr redirected to real files, then `ls -l /proc/<pid>/fd`:

```
$ sleep 300 < /etc/hosts > /tmp/sleep_out 2> /tmp/sleep_err &
[1] 41216
$ ls -l /proc/41216/fd
total 0
lr-x------ 1 hmao hmao 64 ... 0 -> /etc/hosts      # fd 0 = stdin  (redirected to file)
l-wx------ 1 hmao hmao 64 ... 1 -> /tmp/sleep_out  # fd 1 = stdout (redirected to file)
l-wx------ 1 hmao hmao 64 ... 2 -> /tmp/sleep_err  # fd 2 = stderr (redirected to file)
```

This is the FD concept made visible: **the integer (0/1/2) is just an index
into the `files_struct` fd table, and each index points to an opened file**.
That is why shell redirection (`<`, `>`, `2>`) works at all — it just swaps
which file the index points to before the program starts.
